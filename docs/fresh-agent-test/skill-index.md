# Installed skills

The host has these skills installed. Each line is a skill's name and the description the host shows you. To use one, read `<plugin>/skills/<name>/SKILL.md` and follow it (it may point you to files under `references/`).

- **brainbase-benchmarks**: Brainbase Benchmarks (beta, enabled by request): reusable, versioned test suites for one agent — cases, checks (Output, Behavior, File, Command, Model judge), immutable versions, runs with model variants, repetitions and concurrency, baselines, comparison labels and trends, import from JSON/YAML/CSV/bundle/Hugging Face/completed task, export, and the /v2/agents/{agent_id}/benchmarks API. Also covers API bake-offs that run one task across several harnesses and grade the results. Use when the user mentions a benchmark, benchmark run, case, check, variant, baseline, headline score, regression test or model comparison for a Brainbase agent; wants to compare harnesses or models on the same task; asks why a run paused, refused a model, or cannot start on a Cursor, Factory or Qoder agent; or sees benchmark_attempt_id or brainbase_benchmark_* on a task. Not for turn-level evaluations (brainbase-evals), model IDs (brainbase-llm-gateway) or credit mechanics (brainbase-payments).

- **brainbase-cli**: Operate the `brainbase` CLI (`npm install -g @brainbase-labs/cli`): install, `login`/`whoami`, PATs (`token create`, `BRAINBASE_TOKEN`), the `brainbase.agent.yaml` manifest, the folder-to-cloud loop (`agent init|create|pull|push|status|unpack|delete`, `link`/`unlink`, `sync`, `agent versions`, `agent connect|surface`), `task create --wait` and `task logs --follow`, `template`, `skill`, `mcp`, `integrations`, `interface`, `orchestration`, `machine`, `team`, `member`, global flags, `--yes`/`--json` rules, exit codes, environment variables, `~/.brainbase/` state, harness install paths, and the `/v2/cli` control-plane API. Use when the user runs or scripts any `brainbase …` command, edits `brainbase.agent.yaml` or `brainbase-orchestration.yaml`, wires CI with a `bbpat_` token, asks why a push, pull or link failed or what an exit code means, or dispatches a task from a terminal. Concepts (what an orchestration, surface, model or PAT scope is) live in sibling `brainbase-*` skills; command syntax lives here.

- **brainbase-evals**: Brainbase evaluations (evals): the automatic judge checks that score every finished agent turn, the `evals` block in `brainbase.agent.yaml`, `brainbase agent eval list|runs`, the `/v2/agents/{agent_id}/evals` and `eval-runs` API, agent-as-judge, verdict statuses, credits and write credentials, and eval-driven development. Use when the user wants to add, edit, enable, disable, archive or read evals or verdicts; grade helpfulness, policy or workflow behaviour across tasks; judge one agent with another; debug `agent push` refusing to archive an eval, `agent_credential_refused`, `origin_unavailable` or errored verdicts; or set up a test-and-iterate loop with structured scores. Also use when a manifest carries an `evals:` list, a task shows EVAL VERDICTS, or `judge_model`/`judge_agent` comes up, even if nobody says "Brainbase". Versioned benchmark runs belong to brainbase-benchmarks, PAT scopes in depth to brainbase-permissions, credit mechanics to brainbase-payments.

- **brainbase-interfaces**: Brainbase Interfaces: private dashboards an agent builds for the people who use it. Covers when to use one, which harnesses can build one (kafka_cloud, Claude Code, Codex, Qwen Code, OpenCode) and which cannot, creating one (name, address, PUT /v2/interfaces/{interface_id}/address), the audience (everyone in the organisation or up to 2,000 chosen people, who also need agent access), building in a conversation (versions, builds, releases, the one-conversation hold), Preview and preview links, editing source, publishing and the two-messages rule, what a dashboard can do, roll back, archive, restore, and every brainbase interface command. Use when the user mentions an interface, dashboard, Interfaces tab, Build in chat, Start building, Publish, `brainbase interface`, `task create --interface`, or wants people who do not build an agent to use it. Slack and chat are brainbase-surfaces; machine preview URLs are brainbase-sandboxes; roles are brainbase-permissions.

- **brainbase-llm-gateway**: Models and model routing on Brainbase: the catalog with exact model IDs and providers, the default model per harness, GET /v2/models, auto and auto:open routing, which models run on which harness, setting default_model or model on agents, threads and tasks, switching a running task's model (PATCH /v2/tasks/{task_id}, brainbase task update --model), Bring Your Own Bedrock for Kimi K3, vendor keys for Cursor/Factory/Qoder (missing_required_secret), harness tracking through the model proxy (--track, BRAINBASE_PROXY_URL), AWS Marketplace model access and Bedrock Mantle quotas, retired IDs, and per-model token prices from the changelog. Use when the user asks which model to pick, what a model's ID is, why a model is refused on a harness, how to change an agent's or task's model, or about BYOK or Bedrock, even without saying "Brainbase" (a default_model line in brainbase.agent.yaml, a kafka_cloud harness, a 400 on auto). Credits and billing: brainbase-payments; harness choice in general: brainbase-platform.

- **brainbase-memory**: Agent memory on Brainbase: the structured, persistent tables an agent reads and writes across tasks, the built-in memory_tables / memory_schema / memory_sql tools, creating tables in the console Memory area, capabilities.memory in brainbase.agent.yaml, the memory MCP the CLI installs and BRAINBASE_MEMORY_MCP_URL, and shared memory across an orchestration. Use when the user asks how a Brainbase agent remembers things between tasks, wants an agent to keep customer context, status queues or reference data, sees memory_* tool calls in a task, wants to turn memory off or on (capabilities.memory: false, memory_enabled), asks whether something belongs in memory or in a playbook, instructions, a skill, Secrets or the Filesystem, or wants every agent in an orchestration to share one memory. Not for sandbox RAM or machine sizes (brainbase-sandboxes), orchestration graphs and triggers (brainbase-orchestration), or the other built-in MCPs (brainbase-tools).

- **brainbase-orchestration**: Brainbase orchestrations: directed graphs of agents with described handoff edges and `create_task_for_<recipient>` tools; schedule, app-event and webhook triggers; scheduled agents; the `brainbase-orchestration.yaml` manifest and `brainbase orchestration` CLI; the `/v2/orchestrations` and templates APIs; what members share (orchestration secrets, MCP servers, shared memory, Cloudflare file handoffs); Kafka workflows versus orchestrations. Use when the user wants agents to hand work to each other, an agent on a cron schedule, an agent started by a Linear/GitHub/app event or a webhook URL, or mentions `brainbase-orchestration.yaml`, `orchestration push --graph-only`, a 409 adding an agent to a second orchestration, inherited secrets or MCP servers, `GET /v2/orchestrations`, edge `settings`, `configured_props`, or workflow triggers and nodes. Not for agent-level tools (brainbase-tools), Slack or meeting surfaces (brainbase-surfaces), or memory tables (brainbase-memory).

- **brainbase-payments**: Money on Brainbase, in two parts. (1) Payments (beta): an agent asks to buy something, the wallet owner approves or declines in Link, the outcome returns to the task; the Payments page, Cancel and Recover request, purchase requests from Slack. (2) Credits and billing: the prepaid credit wallet (1 credit = $0.01), buying credits, auto top-up with a threshold and reload amount, signup and Team-upgrade credits, project spend limits, enterprise invoices and cards on file, AWS Marketplace billing, the pricing page's plans, and what consumes credits (model calls, sandbox and GPU time, eval judges, benchmark runs, meeting minutes, Claude Code and Codex subagents, image generation). Use when a task failed for lack of credits, the user asks what a sandbox, benchmark or meeting costs, how to top up or cap a project's spend, how invoices work, or how an agent can make a purchase. Per-token model prices: brainbase-llm-gateway; sandbox providers: brainbase-sandboxes; roles: brainbase-permissions.

- **brainbase-permissions**: Access control and credentials on Brainbase: organizations, projects/teams/groups, members and roles (owner, admin, member, agent manager); personal access tokens (bbpat_…) with read/publish/admin scopes versus login sessions, API keys, task keys (bb_live_…) and sandbox-scoped credentials; which /v2/cli endpoints check which scope; strict-admission codes (agent_credential_refused, credential_scope_denied, cross_context); Allow/Ask/Deny rules for connected apps and who may answer an Ask; secrets storage and inheritance; interface audiences; remote MCP allowlists; spend limits; SSO. Use when the user asks who can do what, hits 401/403 from api.brainbaselabs.com or the brainbase CLI ("PAT lacks required scope", "jwt_required", "CLI task keys cannot manage cloud configuration"), needs a CI token, must change a member's role or project access, wants an agent to ask before an app action, or asks how secrets reach a sandbox. App tools: brainbase-tools; wallets: brainbase-payments; dashboards: brainbase-interfaces.

- **brainbase-platform**: Orientation for the Brainbase agent platform and home of its shared concepts: agents, harnesses (`kafka_cloud`, `claude_code`, `codex`, …), sandboxes, surfaces, tasks, threads and turns; the Universal Harness API (`POST /v2/threads` with an inline agent spec or `agent_id`, spec dedupe, thread statuses, messages, follow-up inputs with `input_id`/`expected_generation`, interrupt, events stream, agents, templates, alerts, authentication); agent configuration basics (instructions, playbooks, modes, versions and pinning, secrets); monitoring and steering tasks; migration from Kafka Legacy; and a routing table to the other brainbase-* skills. Use when the user mentions Brainbase or Kafka, `api.brainbaselabs.com`, a Brainbase agent/task/thread id or harness value, asks how to start, watch, steer or stop an agent over the API, what `need_more_info` means, or which Brainbase skill applies. Open this first when unsure; it hands off to brainbase-cli, -llm-gateway, -sandboxes, -orchestration and the other siblings.

- **brainbase-sandboxes**: Brainbase sandboxes and machines: providers (daytona, e2b, cloudflare, modal, bbsandbox, aws_microvm), sizes S/M/L, GPU sandboxes, hourly prices and credit billing, machine_kind and machine_size in the agent spec, manifest and task, the /v2/machines API and `brainbase machine ls|rm`, the entrypoint script, the agent file system at /workspace/Shared, task files, shared files and 1 GiB file-transfer APIs, chat attachments, preview URLs, Cloudflare sleep/resume and file handoffs, AWS MicroVM quotas. Use when the user asks where an agent runs, which provider or size to pick, what a sandbox costs or why one still bills, how to tear one down, how to install dependencies before the agent starts, how to get files in or out of a task or shared folder, how to preview an app the agent serves, or hits machine_not_ready, machine_terminal, interface_preview_only or shared_transfer_not_available. Wallets: brainbase-payments. Secret scopes: brainbase-permissions. Browser: brainbase-tools.

- **brainbase-skills**: Skills on the Brainbase platform: portable SKILL.md packages an agent installs from the Brainbase registry, GitHub or git; `brainbase skill add|list|update|remove|search|info|publish`; the `skills:` list in `brainbase.agent.yaml` and the `skills` field of the agents API (`registry:creator/slug@1.2.3`); where installed skills land on each harness; publishing a skill to the registry; and when to use a skill rather than instructions or a playbook. Use when the user mentions a Brainbase skill or the skill registry, runs `brainbase skill …`, edits `skills:` in a `brainbase.agent.yaml`, passes `skills` to `POST /v2/agents`, asks why an agent cannot find a skill it installed, wants to publish or pin a skill version, or asks whether something belongs in instructions, a playbook or a skill. Not for Claude Code skills in general, for templates and the rest of the CLI (`brainbase-cli`), or for the Brainbase MCP's skill tools (`brainbase-mcp`).

- **brainbase-surfaces**: Brainbase surfaces: the channels where people reach an agent (chat, Slack, Linear, GitHub, phone, meetings), connecting and configuring each from the console or `brainbase agent connections|connect|disconnect|surface`, what the agent can do on each (Slack progress, stop, approvals and coding tasks; Linear delegation and mentions; GitHub PR reviews, @mentions and pushing; phone numbers and whitelists; meeting calendar auto-join and billing), and which steps need a login session, not a PAT. Use when the user wants an agent in Slack, Linear, GitHub or Teams, a phone number, meeting notes or PR reviews from a Brainbase agent, asks what an agent is connected to, asserts connections in CI, or picks a deployment channel; also on `agent connect`, `BRAINBASE_SLACK_BOT_TOKEN`, a Slack manifest or GitHub App for a `brainbase.agent.yaml` agent. Not for Pipedream apps or MCP servers (`brainbase-tools`), dashboards (`brainbase-interfaces`) or triggers (`brainbase-orchestration`).

- **brainbase-tools**: Brainbase tools, everything that lets an agent act outside the conversation: integrations (Pipedream apps, the `brainbase-apps` MCP server, Allow/Ask/Deny, `operation_id`, error codes, `bb-apps`, integrations from your own code), MCP servers (remote vs command, public-HTTPS rule, manifest `mcp` block, `brainbase mcp list|connect|check`, orchestration-shared servers, Override/Suppress, `${NAME}` secrets), built-in MCPs (orchestration, memory, browser, Slack, meeting, GitHub, Linear) and URL overrides, functions, browser and proxies, AppFactory, image generation, web search, the Brainbase MCP for Claude Code/Codex/ChatGPT, and the first-MCP-server tutorial. Use when the user mentions MCP, `mcp_servers`, `brainbase integrations`, connecting Gmail/Slack/Notion to an agent, `needs_connection`, `outcome_unknown`, an approval card, a Tools page, or `mcp:`/`capabilities:` in `brainbase.agent.yaml`. Skills: brainbase-skills; memory tables: brainbase-memory; channels: brainbase-surfaces; roles: brainbase-permissions.
